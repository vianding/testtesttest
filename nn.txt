I think the current plan is solving a simplified endpoint-preserving conversion, but not the actual requirement.

The requirement is not simply:

`average hazard pillars -> piecewise-flat forward hazard pillars -> register as Hazard Rate`.

The requirement is to add a new market input type whose native representation and risk space are **Average Hazard Rate / Credit Zero Rate**, matching RW’s zero-rate curve construction.

Key points:

1. RW input is sparse zero-rate / average-hazard nodes with **linear interpolation in zero-rate space**:
   [
   a(t)=\text{linearInterp}(a_i)
   ]

2. The survival curve should be evaluated as:
   [
   Q(t)=\exp(-a(t)t)
   ]

3. Therefore the model should preserve this curve definition at actual evaluation dates, especially:

* bond cashflow dates
* risk dates
* curve pillar dates
* any internal dates used by the pricing/risk engine

4. The formula:
   [
   h_k=\frac{a_k t_k-a_{k-1}t_{k-1}}{t_k-t_{k-1}}
   ]
   only creates a piecewise-flat forward hazard that matches survival at pillar endpoints. It does **not** fully preserve RW’s linear-zero interpolation between sparse points.

5. If the engine internally requires flat-forward hazard, we can still convert to internal hazards, but the conversion should be based on the actual evaluation grid. For each interval ([u_{j-1},u_j]), define:
   [
   H(u)=a(u)u
   ]
   [
   h_j=\frac{H(u_j)-H(u_{j-1})}{u_j-u_{j-1}}
   ]
   where (a(u)) is RW-style linearly interpolated zero/average hazard.

6. Risk should be analytic/Jacobian-based, not primarily bump-and-reval.
   The reported risk should be:
   [
   \frac{\partial PV}{\partial a_i}
   ]
   where (a_i) is the input zero-rate / average-hazard node.

7. The Jacobian needs to include interpolation weights. For any evaluation date (u) between input nodes (t_i,t_{i+1}):
   [
   a(u)=w_i(u)a_i+w_{i+1}(u)a_{i+1}
   ]
   [
   Q(u)=\exp(-a(u)u)
   ]
   so:
   [
   \frac{\partial Q(u)}{\partial a_i}
   =
   -uQ(u)w_i(u)
   ]
   and similarly for (a_{i+1}).

8. If we convert to internal piecewise-flat hazards on an evaluation grid, the chain rule should be:
   [
   \frac{\partial PV}{\partial a_i}
   =
   \sum_j
   \frac{\partial PV}{\partial h_j}
   \frac{\partial h_j}{\partial a_i}
   ]
   where:
   [
   h_j=\frac{H(u_j)-H(u_{j-1})}{u_j-u_{j-1}}
   ]
   and:
   [
   H(u)=a(u)u
   ]
   This Jacobian is not just the simple bidiagonal node-to-node formula unless the evaluation grid equals the sparse input pillar grid.

9. Bump-and-reval can be used only as a validation check:

* bump one average-hazard input node by 1bp
* rebuild RW-style linear-zero curve
* rebuild survival/internal hazard curve
* compare finite-diff result to analytic Jacobian risk

But the implementation should be analytic-first.

So please revise the plan from “convert sparse average-hazard pillars into hazard pillars” to “add native AverageHazardRate / CreditZeroRate input with RW-style linear-zero interpolation and analytic Jacobian back to input nodes.”
