Please implement a new market input type for the existing credit model: **Average Hazard Rate** / **Credit Zero Rate**.

Context:

* RW provides continuously-compounded zero rates, linearly interpolated between tenor dates.
* In credit-model terms, these zero rates correspond to **average hazard rates**, not flat-forward hazard rates.
* Current `Hazard Rate` input treats the supplied values as instantaneous / flat-forward hazards, which gives the wrong survival-curve shape when the zero curve is nonzero and sloped.
* We want the model perturbation space and reported risk to be in zero-rate / average-hazard space.

Required behavior:

1. Add a new input type, e.g. `AverageHazardRate` or `CreditZeroRate`.
2. Interpret input node value (a_i) at time (t_i) as:
   [
   a_i = H(t_i)/t_i
   ]
   where (H(t)) is cumulative hazard.
3. Construct survival probability as:
   [
   Q(t_i)=\exp(-a_i t_i)
   ]
4. If interpolation is required between nodes, preserve RW-style linear interpolation in average hazard / zero-rate space:
   [
   a(t)=\text{linearInterp}(a_i)
   ]
   and:
   [
   Q(t)=\exp(-a(t)t)
   ]
5. If the pricing engine internally requires flat-forward hazard, convert from cumulative hazard:
   [
   H_i=a_i t_i
   ]
   [
   h_i=\frac{H_i-H_{i-1}}{t_i-t_{i-1}}
   ]
   but keep the risk perturbation/reporting space as average-hazard / zero-rate space.

Risk/Jacobian requirement:

* The reported sensitivity should be with respect to the average-hazard node (a_i), not survival probability and not forward hazard.
* For survival-probability conversion:
  [
  \frac{\partial Q_i}{\partial a_i}=-t_i Q_i
  ]
* Therefore:
  [
  \frac{\partial PV}{\partial a_i}
  ================================

  \frac{\partial PV}{\partial Q_i}
  \cdot (-t_i Q_i)
  ]
* A 1bp bump should mean:
  [
  a_i \rightarrow a_i + 0.0001
  ]
  or for flat CS01:
  [
  a(t) \rightarrow a(t)+0.0001
  ]

Validation tests:

1. If all average-hazard inputs are zero, output should match the existing zero-credit-spread / hazard-zero case.
2. For a nonzero sloped zero curve, survival should match:
   [
   Q(t)=\exp(-a(t)t)
   ]
   at both pillar dates and tested interpolation dates.
3. Flat +1bp average-hazard shift should reproduce zero-rate CS01 behavior.
4. Bucketed KRS should be reported in average-hazard / zero-rate space, not forward-hazard space.
5. Compare against the old `Hazard Rate` input to confirm differences appear only when the input zero curve is nonzero/sloped.

Implementation preference:

* Avoid overloading existing `Hazard Rate` or `Survival Probability` semantics.
* Add a clearly named input mode so curve construction and risk bump space are explicit.
* Keep CDS spread logic out of this path; CDS bootstrap/recovery is not relevant for this use case.
